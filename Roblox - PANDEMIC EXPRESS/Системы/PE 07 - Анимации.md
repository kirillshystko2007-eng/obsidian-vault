# Система анимаций
Связано: [[PE 05 - Персонаж и респавн]], [[PE 06 - Downed и смерть]], [[PE 08 - Револьвер]], [[PE 09 - Dual stance]], [[PE 13 - NPC]].

Контент расположен в `ReplicatedStorage.Animations` (KeyframeSequence) и разрешается через `AnimationIdResolver`. Набор включает idle/walk/strafe/back/hurt-walk, slide/jump, revolver draw/aim/shoot/reload, fists, death, chairs и NPC/zombie clips.

- Игрок: `StarterPlayerScripts.CharacterAnimator` отвечает за локомоцию на клиенте, чтение input/health, idle variants, оружейные позы и клиентские выстрелы других игроков.
- Револьвер: скрипт `ServerStorage.Revolver.RevolverAnimation` находится внутри шаблона Tool и управляет визуальным rig, клипами, reload и звуком владельца.
- NPC: `ServerScriptService.NPCAnimator` использует те же clips, если NPC не помечен как custom. `IdleAnimation` и `WalkAnimation` — имена KeyframeSequence.
- Смерть: `DeathAnimations` вызывается для игрока/NPC; часть клипов `Death1..Death4`.

### Публикация (G21, 2026-11-18)

Все клипы `ReplicatedStorage.Animations` загружены как Animation-ассеты аккаунта-владельца игры (userId 2720869377) через Open Cloud. У каждого `KeyframeSequence` два атрибута:

- `AnimationId` — id ассета. Вне Studio `AnimationIdResolver` берёт **только** его; в Studio по-прежнему живая регистрация (правки в Animation Editor видны сразу). Проверить опубликованные id в Studio: атрибут `ReplicatedStorage.UsePublishedAnimationsInStudio = true`.
- `AnimationSig` — отпечаток клипа в момент загрузки (`AnimationIdResolver.signature(ks)`: настройки + все ключи, позы, маркеры). При каждом тесте в Studio сервер один раз проходит по всем клипам. Если у клипа нет id или клип изменён после загрузки (в живой игре тогда играет **старая** версия), резолвер пишет по одному warning на каждый вид проблемы со списком клипов. На клиенте не проверяется: повороты поз приходят туда сжатыми.

**Как перевыпустить изменённый клип** (обновить содержимое существующего ассета Open Cloud разрешает только для .fbx, поэтому — новый ассет):
1. Studio → `.rbxm`: `SerializationService:SerializeInstancesAsync({ks})` → мост `anim_bridge.mjs` (127.0.0.1:8765, есть в HTTP-allowlist ассистента) → `Documents\PandemicExpress_Monsters\out\anims\<Имя>.rbxm` (папка одобрена для загрузки).
2. `open_cloud_invoke` POST `/assets/v1/assets`, `assetType: Animation`, `fileContent` = файл (`model/x-rbxm`), потом GET `/assets/v1/operations/<id>` до `done`.
3. Новый id → атрибут `AnimationId`, `AnimationSig = signature(ks)`.
4. Новый клип, добавленный в `Animations`, проходит те же шаги — иначе warning «no published AnimationId».

Скрипты, которые грузят клипы, обязаны идти через `AnimationIdResolver` (не через `KeyframeSequenceProvider` напрямую). В G21 на резолвер переведены `EmoteWheel`, `CultistIdleLoop`, `SheriffIdleLoop`, `ContrabandistIdleLoop`, `Flyer.InspectAnim` (обе копии). `cultistidle2` из `RBX_ANIMSAVES.Cultist` скопирован в `Animations.CultistIdle2`, чтобы получить id. Отчёт: [[PE Отчёт 2026-11-18 — G21, публикация анимаций]].

### Типовые причины поломки

Неверный asset-id/регистрация sequence между Studio и live, имя clip отличается регистром, отсутствуют `WeaponRig`/`AnimationController`/attachments, R6/R15 mismatch, старый tool-script остался в шаблоне, более поздний idle перебивает aim. Для проверки сравни source/target анимацию и персонажа в Play test; runtime пока не проверялся. См. [[PE 08 - Револьвер]] и [[PE 13 - NPC]].
