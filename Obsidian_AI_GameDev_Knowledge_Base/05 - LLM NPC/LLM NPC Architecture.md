# LLM NPC Architecture / Архитектура NPC на базе языковой модели

LLM может генерировать диалоги, интерпретировать свободный ввод и предлагать действия персонажа. Но LLM не должна напрямую владеть критичным игровым состоянием.

## Рекомендуемая архитектура
Player input + canonical game state + character profile + memory retrieval
→ prompt/context builder
→ LLM
→ structured response
→ schema validation
→ game-rule validation
→ dialogue/action executor
→ event log.

## Разделение ответственности
- LLM: формулировка реплик, выбор из разрешённого набора намерений, суммаризация памяти.
- Game engine: здоровье, инвентарь, экономика, квестовые флаги, урон, права доступа.
- Validator: проверка формата и допустимости предложенного действия.

## Память
- Working memory: текущий разговор.
- Episodic memory: важные события персонажа.
- Semantic memory: устойчивые факты о мире/персонаже.
- Retrieval: поиск релевантных фрагментов по запросу.

Не сохраняйте каждый токен диалога как вечную память. Нужны политика записи, дедупликация, срок жизни и возможность исправления.

## Основные риски
Latency, стоимость, недетерминизм, prompt injection, утечка скрытых данных, lore drift, небезопасный вывод, сетевой отказ.

## Практический MVP
1. NPC отвечает только на диалог.
2. Добавить persona и ограниченный lore.
3. Добавить память о 3-5 важных событиях.
4. Ввести структурированный JSON output.
5. Добавить список допустимых игровых действий.
6. Проверять каждое действие в движке.
7. Добавить fallback на локальные реплики.
