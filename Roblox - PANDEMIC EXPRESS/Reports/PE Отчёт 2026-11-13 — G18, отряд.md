# PE Отчёт 2026-11-13 — G18, отряд

Связано: [[PE_Goals_00_Roadmap|G18]] · [[PE 33 - Рейд - сумка, могила, сохранение, вина]] · [[PE Дизайн 03 — PvP, безопасные зоны и вина]] · [[PE Отчёт 2026-11-12 — G17, ценности и скупщики]]

## Что сделано
Игроки могут собраться в **отряд (posse) до 4 человек**:
- **Без урона между своими.** `PvPRules.canHurt` отказывает, если у стрелка и жертвы одинаковый `PosseId`. Все виды оружия по игрокам уже спрашивают `canHurt` (револьвер, кулаки, толчок, нож, ружья), так что вины за своих тоже нет.
- **Общий поезд.** Когда **лидер** садится на поезд (или бронирует следующий), участники в радиусе **45 студов** от него садятся вместе с ним (или получают ту же бронь). Им пишется «Riding with <лидер>'s posse».
- **Компас.** На полосе компаса HUD у каждого участника отряда есть зелёная метка ▼. Пока метка близко к направлению взгляда, снизу видно имя и расстояние. Своя могила показана как **†** с текстом «YOUR GRAVE 201 · 3:13» (расстояние и сколько ей осталось).
- **Состав слева.** Пока ты в отряде, слева видно имя каждого участника (★ у лидера), полоску здоровья и расстояние (или TRAIN).
- **Метки над головой.** Над участниками отряда видна звезда и имя ★ NAME (только у своих, сквозь стены, до 400 студов).
- **Окно P.** В окне «THE POSSE» показаны твой отряд (у лидера есть кнопка SEND OFF, у всех LEAVE THE POSSE) и игроки на сервере, ближние первыми, с кнопкой INVITE (приглашает только лидер или игрок без отряда).
- **Приглашение.** Сверху появляется карточка «X ASKS YOU TO RIDE WITH THEIR POSSE»: **Y** принять, **N** отказать (или кнопки). Через 30 с она пропадает.
- Ушёл лидер — лидером становится следующий. Остался один — отряд распадается. Вышел из игры — убран из отряда.

## Где (DataModel)
| Что | Путь |
|---|---|
| Сервер | `ServerScriptService.PosseService` (новый) — приглашения, вступление, уход, исключение; раз в секунду рассылает участникам их позиции и здоровье (из-за StreamingEnabled далёкий персонаж на клиенте не загружен) |
| Remote | `ReplicatedStorage.PosseRemote` — клиент→сервер `invite / accept / decline / leave / kick` (только Player в игре, не чаще 0.4 с); сервер→клиент `invited / notice / roster / closed` |
| Атрибуты игрока | `PosseId` (число), `PosseLeader` (true) — видны всем клиентам |
| Клиент | `StarterPlayerScripts.PosseClient` (новый) — окно P, карточка приглашения (Y/N), состав слева, метки над головой, метки компаса |
| Компас | `HUD`: новая папка `LocalPlayer.CompassMarkers` (только на клиенте). Любой клиентский скрипт может положить туда `Vector3Value` с атрибутами `Glyph`, `Text`, `Color` — HUD нарисует метку |
| PvP | `ServerStorage.PvPRules`: `PvP.samePosse(a, b)`, проверка в `canHurt` |
| Поезд | `TrainService.book`: блок «лидер забирает отряд», `POSSE_RADIUS = 45` |
| Могила | `GraveService.createGrave` ставит игроку `GraveId / GravePos / GraveExpires`, `removeGrave` снимает их (только если это его последняя могила) |
| Тест | `ServerStorage.PosseDebug:Invoke(cmd, a, b)`: `invite / accept / decline / leave / kick / fake <имя> / roster / state / clear`. `fake` создаёт «двойника» (Folder) для проверок одним игроком |

## Проверка в Play (звук выключен, 1 игрок)
- Логика через `PosseDebug` с 4 «двойниками». Работают: приглашение себя (нельзя), повтор (уже спросил), принятие не от того (не трогает настоящее приглашение — эту ошибку нашёл и исправил), вступление, приглашение от не-лидера (нельзя), 5-й при полном отряде (нельзя), исключение не лидером (нельзя), исключение, отказ, уход лидера (передача или распад), состав с позицией и здоровьем.
- `canHurt(участник, мой Humanoid)` = **false**, `samePosse` с чужим = false.
- Смерть в Gravesend (рейд) → могила #1, атрибуты `GravePos/GraveExpires` поставлены, на компасе метка «7.6k · 4:48» после возрождения в CC. `GraveDebug expire` → атрибуты сняты, метка исчезла.
- `TrainDebug book` лидером → бронь без ошибок (блок отряда отработал).
- Ошибок в логах сервера и клиента нет.
- **Не проверено (нужно 2+ клиента):** настоящее приглашение и ответ Y/N между двумя игроками, отсутствие урона в настоящем бою, посадка участников вместе с лидером, метки над головой и на компасе для живого участника. Тот же блокер, что у G7/G10: Local Server не запускался.

## Откат
- Отряд целиком: удалить `PosseService`, `PosseClient`, `PosseRemote`. Остальные правки без них ничего не делают: атрибута `PosseId` просто нет.
- Бэкапы `ServerStorage._AnimBackup.*_pre_g18_2026-11-13`: `PvPRules`, `TrainService`, `HUD`, `GraveService`.

## Заметка

## Ревью и исправления (2026-11-13, позже)
Проверил свою работу скиллами `gamedev:roblox-networking`, `roblox-ui`, `game-ui-ux`, `input-systems`, `audio-design`, `roblox-studio-workflow`. Отдельный агент-ревьюер прочитал все скрипты отряда. Найдено и исправлено:

| Проблема | Исправление |
|---|---|
| Участников сажали в поезд **до** того, как сел сам лидер: если лидер «занят» или посадка сорвалась, отряд уезжал без него. Двойной тост при смене лидера и при посадке по брони | `TrainService`: старая функция теперь `bookOne`, обёртка `book(player, station, viaLeader)` тянет отряд **после** успешной посадки или брони лидера, только один раз. `boardReserved` вызывает `book(..., true)` |
| Карточка приглашения забирала выбор геймпада: стик управлял меню, A (прыжок) принимал приглашение | карточка выбор не трогает. Геймпад: крестовина ▲ принять / ▼ отказать, подсказки по устройству (Y/N, ▲/▼, на тач без подсказок) |
| Два игрока по очереди могли держать карточку у цели | открытое приглашение другого нельзя заменить: «X is answering another posse» |
| Спам приглашениями после отказа | после «нет» та же пара ждёт 20 с |
| Отказ сервера или срезанный лимитом запрос оставлял кнопку ASKED на 30 с | сервер шлёт `inviteFailed`, кнопка INVITE возвращается. Лимит теперь «ведро» на 4 действия +2/с вместо жёстких 0.4 с |
| Позиции раз в секунду шли надёжным remote | `ReplicatedStorage.PossePulse` (UnreliableRemoteEvent) с номером посылки, клиент берёт только новее. Пустые поля = `false`, чтобы массив не обрывался. Состав отряда идёт по надёжному `PosseRemote` |
| ASKED никогда не показывался (кнопка просто пропадала) | серая неактивная кнопка ASKED |
| Окно пересобиралось каждые 2 с и съедало клики / выбор геймпада | пересборка только при смене людей или кнопок, расстояния и HP обновляются на месте 2 раза в секунду |
| Нет входа с геймпада и тача | кнопка ★ под мешком (P / Y / POSSE по устройству), геймпад Y открывает, B закрывает, выбор на первой кнопке |
| На низком экране окно вылезало за край | масштаб окна ограничен высотой экрана, окно по центру |
| Метка могилы терялась после перезахода | `GraveService.onPlayer` возвращает метку самой свежей могилы игрока |
| Мелочи | «Уменьшить движение» (Reduced Motion) убирает анимацию затухания, карточка поверх окна, `asked` чистится при выходе игрока |

**Звуки (ElevenLabs → Open Cloud):** `posse_invite` 113943395889831 (свист и шпоры, на приглашение), `posse_join` 89919089632015 (рукопожатие и барабан револьвера, при вступлении). Записаны в `PESounds`, промпты в `manifest3.json`. Тон каждый раз чуть разный (±4 %). На слух не проверены.

Карточка: пользователь сам нажал Y во время теста, ушёл `accept`, выбор геймпада карточка не взяла. Ошибок на сервере и клиенте нет.
